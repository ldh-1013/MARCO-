# 사운드 적용 현황

현재 네트워크 맵 `NetworkPool_v1_2`와 연결된 `IndoorPool_v1_2` 대상. 지정받은 원본만 사용하며 18개 클립, 약 5.6MiB다. 원본 제공 폴더와 Git 백업은 별도로 보존한다.

## 적용
- 타일/콘크리트 보행·달리기 발소리: 캐릭터 애니메이션 주기 연동, 동일 클립 연속 선택 방지. 카펫·매트는 타일, 금속 계단·통로는 콘크리트로 임시 대체. 관람석 단상도 포함.
- 술래·도망자 점프 시작/착지음: 기존 바닥/수면 파일 재사용. 제자리 점프 포함, 착지 직후 일반 발소리 중복 억제. 기본 청취 반경 시작3m/착지6m, 역할 배율·차폐 적용.
- 얕은 물 이동음: 양쪽 역할 모두 이동 중 연속 재생하고 발걸음에 따라 음량 강조. 정지/물 밖에서 페이드아웃. 깊은 구역·원형 구덩이·수중 밸브 B/E 상호작용 반경 내는 제외. 얕은 구역은 캐릭터 키/웅크림 때문에 꺼지지 않는다. 마른 발소리 중복 방지.
- 밸브 회전·역류: 기존 서버 이벤트 연결, 회전 중단 시 정지. B/E는 먹먹한 효과 적용.
- 붕대 감기·동료 치료: 기존 채널 작업 중 재생/취소 시 정지.
- 피격음: 첫 적중으로 상처 상태가 될 때 대상 본인에게만.
- 부상 신음: 도망자 목숨1.0, 첫 피격6초 후부터6초 간격.
- 심장박동: 살아 있는 도망자에게 술래8m 이내 접근 시.
- 술래 전용 드론: 살아 있는 술래 본인에게만, 음량.15. 원본의 조용한 가장자리 정리와 .75초 겹침으로 반복 경계 보완.
- 종반 드론: 최신 라운드 코드의 기존 소스 하나에 연결. 잔여2분부터 재생, 중복 소스 없음.

수면 루프도 .2초 반복 경계 겹침을 사용한다. 반복용 작업본은 런타임 메모리에서만 만들며 파형을 강제로 증폭하지 않는다. 잡음이 확인된 Tile_3은 제외했다.

## 미적용/남은 작업
- 술래 외침, 메아리 노크, 도망자/술래 호흡: 해당 재생 연결은 보류.
- 금속·카펫·매트 전용 녹음: 아직 없어서 임시 대체음 사용.
- 밸브 개방 완료음, 찰칵이 전용음, 자동 비명·수중 작업 전용음: 적절한 지정 녹음/연결 없음. 새 에셋을 임의로 추가하지 않았다.
- 별도 콘크리트.wav는 대체 후보로 미사용.
- 새 시각 파문 전달 시스템은 이번 소리 작업 범위에 포함하지 않았다.
- 실제 다인 접속의 청감·음량·거리감·네트워크 지연과 최종 발 디딤 박자는 팀 플레이 확인이 필요하다.

## 검증 도구
별도 Unity 배치 프로세스에서 실행한다. 게임플레이 검사들은 완료 후 에디터를 자동 종료하므로 작업 중인 에디터에서 직접 실행하지 않는다. 씬/프리팹을 저장하지 않는다.
- `Marco.Network.Editor.AudioFloorAudit.Run`: 바닥·계단 분류, 18개 클립 로딩.
- `Marco.Network.Editor.AudioMovementChecks.Run`: 실제 콜라이더 이동의 걷기/달리기 소리, 역할 전환 후 활성 D 밸브 조작.
- `Marco.Network.Editor.AudioWaterChecks.Run`: 술래 이동, 도망자12초 단일 수면 루프, 역할별 드론, 정지·깊은 구역·웅크림·밸브·마른 바닥.
- `Marco.Network.Editor.AudioJumpChecks.Run`: 양쪽 역할의 제자리/이동 점프와 얕은 물의 시작/착지음 각각1회 및 양의 음량.
- 기존 `Marco.Core.WinCondition.Tests` EditMode 테스트로 밸브·역류·승리조건·종반 압박 등 기존 규칙의 회귀 확인.

이동속도·스태미나·키 입력·맵 배치는 팀원 최신 코드를 유지한다. 바닥/물 판정은 오디오 연출용이며 이동·부력·수영 능력 자체를 추가하지 않는다. 팀원은 같은 최신 코드로 Pull 후 실행/빌드해야 한다.
