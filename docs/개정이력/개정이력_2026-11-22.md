### 무엇이 문제였나

- 판정 입력이 서버 이동 틱(0.1초) 하나의 속도였고 경계가 5.0 하나였다. 도망자 걷기 속도가 정확히 5.00이라 틱 속도가 경계 위아래로 흔들렸다(틱의 47%가 5.0 초과).
- 그래서 걷기 중에 등급이 수십 번 바뀌고, 바뀔 때마다 스텝 거리가 0으로 리셋돼 2m 스텝이 이론의 60%만 났다. 걷기 중 6m 질주 파문도 났다.
- 본인 로컬은 프레임 속도의 52%가 5.0을 넘어 0.15초 연속 조건을 못 채웠다. 그래서 처음 등급에 갇혔다(질주 직후 · 웅크려 걷기에서 계속 질주 등급).
- 출처: 기준 `97d4720` · `014341e` · 현재가 같은 코드다. Phase 1 이전부터 있었다(최초 `8bf63c6`).

- 그대로 둔 것:
  - 0.15초 전환 안정화 지연, 전환 시 거리 리셋

## 본인 발소리를 판정 시계에 일치 (V42b 파트 B, 사용자 승인 2026-11-22)

브랜치 `fix/footstep-clock-align`(파트 A 0dbaed7에서 분기). 연출 2.1 "발 닿음 = 판정 = SFX".

### 읽기 전용 확인

- 본인 발소리는 `RoundAudioPlayback.TickFootsteps`가 `CharacterMotion.FootstepIndex`(= floor(걸음 주기 × 2), 애니메이션 위상)가 늘 때 냈다. 판정(`MovementPulseClock`, 거리 2m / 6m)과 다른 시계다.
- 걷기 애니메이션 속도는 `CharacterMotion.GaitPlaybackRate`가 정한다. 5m/s에서 1배이고 `walkCycleDuration` 1.2초(UnityChan · Demon 모두)라 한 주기 6m, 걸음 3m였다.
- V32 걷기 bob 보정(`WalkBobPhase`)은 애니메이션 위상 0 · 0.5(옛 SFX 순간)에 bob 저점을 맞춘다.
- 로컬 판정 펄스는 `RoundAudioPlayback`의 본인 `StepState.Clock`(`Advance`의 반환값)에서 읽을 수 있다.

### 바꾼 것

1. 본인 발소리 SFX를 로컬 판정 펄스(걷기 2m, 질주 6m)에서 낸다.
   - 클립 · 볼륨 · 지속은 그대로다. 소리는 판정 등급을 따르고 5.05(`FootstepRunning`)는 걸음 애니메이션 · 카메라 bob에만 쓰인다 [V43 정정 — 예전: "소리 크기 등급(5.05)은 그대로"].
   - 다른 사람이 듣는 발소리는 서버 스텝이라 바뀌지 않는다.
2. 걷기 애니메이션을 ×1.5로 돌린다(한 주기 4m, 걸음 2m).
3. 본인 걷기는 재생 속도를 ±40% 안에서 조절해 발 닿음(위상 0 · 0.5)을 판정 펄스 쪽으로 끌어 맞춘다 [GAP 이득 2 · 한계 0.4].
   - 위상을 건너뛰지 않으므로 다리 자세가 튀지 않는다.
   - bob 보정이 이 위상에 저점을 두므로 bob도 함께 맞는다.
4. 질주는 애니메이션 · bob을 그대로 둔다(발 닿음 3m). SFX만 판정 6m마다 나므로 **질주 발소리가 예전(3m마다)의 절반으로 드물어진다**.

변경 파일:
- `RoundAudioPlayback.cs`: 본인 SFX 경로, 본인 걷기 판정 위상 공개
- `CharacterMotion.cs`: 걷기 ×1.5, 위상 끌어 맞춤
- `MovementPulseClock.cs`: 읽기 전용 `StepDistance`, 간격 상수
- 서버 · 네트워크 파일은 바꾸지 않았다.

- 그래서 카메라 추종으로 충족되는지 확인했다. 충족된다 — 이동 · 속도 · 위치를 바꾸지 않아도 화면 속 가감속이 같다.

**구현** — 이동 값 · 속도 · 위치 판정은 바꾸지 않았다.

- `Vision/Feel/EchoInertia.cs`(새 파일): 본인 카메라가 실제 위치를 임계감쇠로 따라간다(`SmoothSeconds` 0.10, 프레임 속도에 따르지 않는 정확해 — 30 / 60 / 144 fps 같은 곡선). 회전은 지연하지 않는다.
- `CameraFeelStack.Write`가 메아리 몸(`HasEchoBody`)일 때만 이 지연을 카메라 위치에 더한다. 다른 상태에서는 실제 위치 그대로다.
- 노크 · 청취 · 서버 위치 · 동기화는 `player.transform.position`(실제 위치)을 쓰고 그대로다. 오디오 리스너는 카메라에 붙은 객체라 최대 0.6m 지연된 위치를 따른다 — 사운드 판정(`SoundWorld`)은 플레이어 위치를 쓰므로 영향 없음.

| 출발 | 카메라 속도가 비행 속도의 59%(0.1초) · 91%(0.2초) · 98%(0.3초) — 단조 증가, **오버슈트 0%** (한계 15% 안) |

**실측** (4창, 메아리가 된 도망자가 실제 키로 W 1.5초 → 정지 → W 0.8초 → 바로 S 0.8초, `runs\v43\echo`)

- 실제 위치 속도는 입력 즉시 6.0 m/s(이동은 그대로 — 최대 6.01), 카메라는 따라 올라간다.
- 지연 최대 **0.62m**(상한 0.75m 안), 정상 상태 0.59 ~ 0.62m.
- 정지 뒤 지연: 0.15초에 0.03m, 0.3초에 0.002m. 실제 위치를 넘어서지 않았다.
- 방향 전환(W → S) 순간 카메라 속도는 0을 지나 반대로 올라간다.

**합산 계층 위치 상한(2cm)과의 충돌**

- 2cm 상한은 흔들림(적중 튐 · 노크 · 호흡 등)의 합산용이다. 가감속 지연을 2cm(또는 예시의 10cm)에 넣으면 6.0 m/s에서 시간 상수가 17ms(또는 0.07초 이하)라 0.3초 가감속이 되지 않는다. 0.3초 가감속에는 정상 상태 지연이 0.5m 안팎 필요하다.
- 처리: 지연은 합산 계층 위치 상한 **밖**에 둔다(걷기 bob 위상 보정과 같은 방식). 흔들림의 2cm · 0.8° 상한은 그대로 지킨다. 지연 자체의 상한은 별도로 **0.75m**를 둔다. [GAP]
- 이것이 사용자 예시(10cm 이내)와 다르다는 점은 보고서에 적었다.

**멀미 위험 자체 평가**

- 회전 지연이 없다: 마우스로 보는 것은 즉시다. 어지러움의 주된 원인(시점 회전 지연)이 없다.
- 지연은 위치뿐이고 부드럽다(임계감쇠, 반동 없음, 0.3초 안). 정지 때 카메라가 0.6m를 미끄러져 멈추는 "부유감"이 의도다(연출 2.2).
- 걱정되는 점: 급정지 · 급전환 직후 벽과의 거리감이 0.6m 어긋난다(메아리는 벽을 통과하므로 충돌 문제는 없다). 벽 통과 노이즈(`TickWallPass`)는 그려지는 카메라 위치를 기준으로 하므로 화면과 일치한다. 불편하면 `SmoothSeconds`를 줄이면 된다(0.05초 = 지연 0.3m).
- 수동 확인 필요: 실제 PC에서 메아리로 급가속 · 급정지 · 360도 선회를 해 보아 멀미가 나는지.
