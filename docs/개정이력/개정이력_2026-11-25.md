# 개정이력 2026-11-25

## V61 — 같은 PC 테스트용 인증 프로필 인자 `-profile <이름>` (브랜치 `fix/auth-profile`, 사용자 요청 2026-11-25)

### 배경 (V60 읽기 전용 분석)

- 같은 PC에서 호스트와 클라이언트를 함께 실행하면 둘 다 같은 Unity Authentication 익명 플레이어 ID로 로그인한다(프로필을 나누지 않음). 방 참가 시 "방 참가 실패: (409) HTTP/1.1 409 Conflict"가 났다(`UnityRelayLobby.cs`의 `JoinLobbyByIdAsync`, 로그 확인).
- 이것은 같은 PC에서 두 창을 쓰는 테스트에서만 생기는 문제이고, 서로 다른 PC에서는 생기지 않는다.

### 바꾼 것 (방 입장 · Relay 흐름은 그대로, 인증 직전 한 곳)

- 실행 인자 `-profile <이름>`이 있으면 익명 로그인 직전에 `AuthenticationService.SwitchProfile(<이름>)`을 부른다(`UnityRelayLobby.cs`, 익명 로그인 호출 앞). 이미 로그인된 경우에는 `SwitchProfile`이 예외를 내므로 로그인 전에만 부른다.
- 이름은 Unity Authentication 프로필 규칙(영문 · 숫자 · `-` · `_`, 30자 이내)을 따른다. 맞지 않으면 무시하고 로그 한 줄(`[Unity Auth] -profile 값 무시…`)만 남긴다.
- 인자가 없으면 코드 경로는 기존과 같다(기본 프로필).
- 인자 해석은 순수 함수 `AuthProfileArgs.Parse`로 분리했고 단위 테스트 11개를 추가했다(없음 / 유효 / 무효 / 대소문자 / 값 없음).
- 서버 · FishNet · `NetworkRound*` · `PlayerMovement*` 파일, 새 RPC · SyncVar는 없다.

### 같은 PC 테스트 실행 방법

- 창 1: `MARCO.exe -profile A`, 창 2: `MARCO.exe -profile B` — 서로 다른 플레이어 ID로 로그인한다.
- 이전에 쓰던 프로필(인자 없음)은 그대로 기본 프로필이다.

### 확인 (같은 빌드, 같은 PC, 로비 시작 후 22초)

| 실행 | 로그 |
|---|---|
| `-profile A` | 프로필 A · 플레이어 ID `4D6tqgVD…` |
| `-profile B` | 프로필 B · 플레이어 ID `toX4LOvG…` (A와 다름) |
| `-profile default` | 프로필 default · 플레이어 ID `SjTW8Z6h…` |
| `-profile a.b` | 값 무시 로그 한 줄, 기본 프로필로 로그인 |
| 인자 없음 | 로그 없음(기존 경로) |

- 방 만들기 · 참가는 로비 화면 조작이 필요해 이번에는 하지 않았다. 두 창이 서로 다른 ID가 되는 것까지만 확인했다.
- 검증: 컴파일 오류 0, EditMode 715 / 715(건너뜀 0), RippleServerChecks · MovementPulseChecks PASS, 서버 키워드 grep · RPC -A6 빈 결과.
