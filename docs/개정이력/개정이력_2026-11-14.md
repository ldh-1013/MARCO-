## 위임 결정 — 노크 소리 (사용자 위임 11-14)

17절 "웃음 오디오" 행의 "메아리 노크 콩콩 리듬은 의도적으로 귀엽게"는 다음 규칙과 충돌했다.

- 3.2 "술래가 노크와 실제 대화 · 비명을 구분할 시각적 · 청각적 단서는 없다"
- 5.1 구분 불가 그룹(비명 · 노크 · 신음)
- 연출 7.2(노크 표현) · 연출 11 "노크와 대화를 구분되게 표현" 금지

결정(같은 날 수정): 노크는 새 에셋 없이 **신음 클립(`Moan_0` · `Moan_1`)** 중 하나를 각 클라이언트가 무작위로 골라 낸다. 볼륨 · 재생 경로 · 차폐 · 잠수 필터 · 방향 힌트까지 신음과 같다. 웃음은 소리가 아니라 반전(가짜 실루엣을 쫓아간 술래)에서 나온다. 17절 행은 노크 부분만 고쳤고 고무오리 부분은 그대로다.

- **비명 클립을 뺀 이유.** 실제 비명은 술래 외침 직후에만 난다(3.5). 외침 없이 들린 비명은 시점만으로 노크라고 식별된다.
- **신음을 고른 이유.** 신음은 노크와 등급이 같고(9m · 1.2초, 부록 A [소리 등급]) 시점 제약이 없다(상처 상태에서 6초 주기).
- **볼륨.** 서버가 노크를 신음 발생 호출과 같은 볼륨(0.65)으로 보낸다. 신음 호출이 숫자 0.65를 직접 쓰고 있어 같은 값을 그대로 썼다(공용 상수로 바꾸려면 신음 호출도 고쳐야 해서 이번 범위 밖).

**[같은 날 결정 2에서 정정]** 첫 반영본의 "구현 미적용"은 서버 볼륨 인자(0f)를 바꿀 허용이 없어서였다. 같은 날 허용을 받아 노크 호출의 `playAudio`와 볼륨 두 인자만 바꿨다(변경 전 원문은 아래).

## 같은 날 후속 (2026-11-14) — 스윙 외형 · 기계실 · phase 11 (코드 변경 없음)

### 스윙 외형 — 미해결

- 스윙은 클립 재생이다. `CharacterMotion.cs` LateUpdate가 공격 중 mixer 입력 3(`Demon|Punch1`, 0~0.8초 구간)을 가중치 1로 재생하고(하체 이동 클립도 대체), 시작은 서버가 스윙을 받아들인 뒤의 `SwingObservers`(`PlayerInteractor.cs:390-393`)다. 적중 · 헛스윙이 같은 모션이다.
- 시도한 조정: 클립 뒤에 팔꿈치를 굽히는 두 뼈 보정(손이 루트에 따로 붙은 Demon 구조는 수영 포즈와 같은 방식으로 따라오게 함)으로 손끝 수평 거리를 판정 반경에서 발톱 여유 0.08을 뺀 값으로 제한. 에디터에서 상한 1.2m로 시험하면 최대 1.18m(손 분리 없음)였다.
- **멈춘 이유**: 상한을 실제 판정 값(`NetworkRound.TagRadius`)에 연결하자 게임에서 제한이 걸리지 않았다. 실제 판정 반경이 **3.6m**(1.2 × 3, 미정 28)이기 때문이다. 4창 실키에서 1.0 · 1.15 · **1.3m**에 선 도망자가 모두 적중했고(서버 로그 7건), 손끝 도달은 적중 · 헛스윙 · 정지 · 걷기 모두 1.62~1.66m(차이 0.04m 안), 손 분리 없음(손-아래팔 거리 변화 0.05m 이하), 팔꿈치 최소 66.9°였다. 상한을 1.2m로 고정하면 판정(3.6m)보다 손이 훨씬 짧아져 "안 닿았는데 맞음"이 더 커진다. 판정 기준이 정해질 때까지 코드는 넣지 않았다.
- 정정: 같은 날 결정 4의 태그 고정 시험표(간격 0.5 / 1.0 / 1.19 / 1.21m)는 모든 간격이 3.6m 안이라 1.2m 경계를 시험한 것이 아니다. 축소 전후 결과가 같다는 결론(432칸 동일)은 그대로 유효하다. 연출 15.1 비고의 "판정 1.2m"도 실제 값으로 고쳤다.

### CombatHudChecks phase 11(외침) — 기존 실패, 점검 코드 문제

- 증상: "Owner shout request enters preparation and locks movement"에서 실패. 점검(`CombatHudChecks.cs` phase 11)이 `PlayerMovement.BeginShoutServer`를 리플렉션으로 부른 **같은 프레임**에 `shoutPending`을 읽는다. 그런데 `BeginShoutServer`는 `[ServerRpc]`(`PlayerMovement.Shout.cs:66-67`)라 호스트에서도 RPC로 전달되어 다음 틱에 처리된다.
