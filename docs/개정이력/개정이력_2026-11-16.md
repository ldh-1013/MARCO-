### V20 지시 오류 정정 — 관전자 제외 → 포함

`EchoBodyRules.HasEchoBody`는 `Tagged · Escaped · Spectating`(난입자)을 메아리 몸으로 본다. 일반 파문 경로(`NetworkRound.EmitSound`)는 메아리 몸 모두에게 보내는데, V20 지시로 질식 링만 `Spectating`을 뺐다. 이를 되돌려 **질식 링도 메아리 몸 전부(난입자 포함)에게 보낸다**(`DrowningPulseRules.For`의 관전자 분기 삭제). 테스트 "관전자 → 안 보냄"을 "Spectating → 보냄(메아리 몸 값)"으로 바꿨다. 위 후속 2 표의 "관전자 — 받지 않음" 행과 수동 테스트 5의 "관전(난입자) 화면에는 없는지"는 이 정정으로 무효다.

잔류 흔적의 시작 투명도를 "링이 끝나는 순간의 투명도"로 하면 0이다 — 링 투명도는 `MaxAlpha × (1 − t)^1.25`(`WalkingFootRings` `Draw`, `RippleVisualSettings.FadePower`)라 t = 1에서 정확히 0이 된다. 시작 투명도를 정하기 전에는 잔류 흔적을 그릴 수 없고, 표시 시간만 ×1.0으로 줄이면 메아리 화면에서 링이 잔류 없이 빨리 사라지므로, 1(서버 표시 시간)과 2(잔류)를 함께 보류한다. 결정 필요.

## 같은 날 후속 4 (2026-11-16) — 메아리 링 정정(A) 재개 · 잔류 시작 투명도 결정 · RPC 서명 검사 규칙 교체

### 결정 — 잔류 시작 투명도 (사용자 승인 2026-11-16)

후속 3에서 보류한 이유: 생존자 링 투명도 `MaxAlpha × (1 − t)^1.25`는 t = 1에서 0이라, 끝 순간의 투명도를 잔류에 넘기면 보이지 않는다. 세 안을 비교했다.

| 안 | 내용 | 결과 |
|---|---|---|
| ① 15% 고정 | 잔상(16.4) 15%(`AfterglowAlpha`)를 잔류 시작값으로 | **채택** — 새 수치 없음, "흐릿한 흔적" |
| ② 링 최고 투명도(0.85)부터 | 링이 사라지자마자 진한 흔적이 3초 | 정보량이 크게 늘어 기각 |
| ③ 링 페이드 곡선 조정 | 링이 끝날 때 투명도를 남기고 잔류가 이어받음 | ①과 함께 적용 — **소나 링에만** |

결정: 메아리 몸 시점의 소나 링만 α(t) = R + (MaxAlpha − R) × (1 − t)^1.25(R = `EchoResidualAlpha` = `AfterglowAlpha`, [GAP] — 잔상 15% 차용). 링이 끝나면 마지막 모양 · 반경을 고정한 잔류로 바꾸고 R × (1 − s / 3초)로 0까지 줄인 뒤 지운다(퍼지지 않음). 생존자 · 술래 시점의 링 곡선은 그대로다.

발생원과 청취자가 수면을 사이에 두면(한쪽은 물속, 한쪽은 물 밖, 양방향 — 1199행) 차폐 경로를 두 구간으로 나눠 판정한다. ① 물속 끝점 → 그 바로 위의 수면 점 ② 수면 점 → 물 밖 끝점. 벽 셈은 두 구간을 하나의 경로로 이어서 차폐 셈 단위(같은 계열 합치기 0.7m, 끝점 5cm)로 세고, 수면 통과는 1회로 센다. 거리 판정은 원래 두 끝점 사이의 3D 직선 거리. 같은 쪽이면 직선 판정 유지. 근거: 6.1 1406–1408행, 1199행, 부록 A 3689–3690행, 10.6 2525행의 "수면 통과 ×0.5". 경로의 기하학적 모양은 기획서에 없는 구현 해석이다(11-16).

배경(V24 조사): 수중 끝점에서 데크로 가는 직선은 대부분 물가 바깥에서 수면 높이를 지나 측벽 · 데크 바닥 판(×2)에 걸렸다. 후속 6에서 교습풀 측벽 · 침강부 벽을 차폐로 세면서 배수구 2 작업 파문은 데크 어디서도 들리지 않게 됐다(6.5-3 "침묵 탈출은 불가능하다"와 충돌).

## 같은 날 후속 8 (2026-11-16) — 차폐 재판정 0.25초 · 상향만 구현 (결정 4, 사용자 승인)

결정 원문(부록 A [사운드 차폐] 3530–3532행, 후속 1): 파문이 살아 있는 동안 청취자별로 0.25초마다 다시 판정하되 상향만 한다(못 들음 → 먹먹하게 들음 → 선명히 들음). 상향되면 남은 지속과 경과 시간을 보내고, 선명해지면 링을 경과 위상부터 그린다. 기획서 본문 · 부록 A는 이미 반영돼 있어 이번에는 구현 상태만 기록한다.

### 대상 경로

| 경로 | 재판정 | 비고 |
|---|---|---|
| `EmitSound` → `SoundTarget` | **포함** — 루프 아닌 소리 전부(Hurt · 질식 소리 · 아이템 · 노크 · 신음 · 태그 · 게이트 · 최후 생존자 · 배수구 작업 · 역류 · 붕대 · 치료 등) | 먹먹함으로 오르면 먹먹한 재생, 선명으로 오르면 선명한 재생 + 링(링 대상일 때) · 스냅샷 |
| 외침 · 비명 → `AbilitySoundTarget` | **포함** | 같은 파문의 먹먹한 목소리를 그 자리에서 선명으로 바꾼다 |
| 질식 링 → `DrowningPulseTarget` | **포함** — 선명 상향만 보낸다(링 전용 경로, 소리는 위 `EmitSound("Hurt")`가 따로 따라간다) | |
| 발소리 → `MovementStepTarget` | **제외** | 한 걸음 파문이 0.4 / 0.8초이고 같은 발생원이 걸음마다 새로 판정된 파문을 낸다 — 재판정 상향은 걸음 소리를 겹쳐 재생할 뿐이다. 바닥 링 경로(`RequestFloor`)에는 시작 위상도 없다 |
| 회전 밸브(루프 키) | **제외** | 회전 중 0.25초마다 `EmitSound`가 다시 불려 매번 새로 판정된다(링은 기존대로 2.5초에 한 번) |
| 음성(`PlayerVoice`) | 제외(지시) | 패킷마다 판정 |

추적하지 않는 청취자: 발생원 본인, 메아리 몸(차폐 무시 — 처음부터 선명), 이미 선명히 들은 청취자, 재판정 중 메아리가 되거나 나간 청취자(그때 목록에서 뺀다). 파문 위치는 발생 시점 값으로 고정한다.

### 구현

| 항목 | 내용 |
|---|---|
| 주기 | `PulseSpec.OcclusionRecheckSeconds = 0.25`(부록 A 3530행 인용 주석) |
| 순수 함수 | `RecheckRules.State(heard, muffled)` · `Upgrade(old, now)` · `Remaining(total, elapsed)` · `Phase(total, elapsed)` · `Send(old, now, total, elapsed)` · `Tracks(own, echoBody, looping, selfOnly, initial)`, 상태 `HearState { None, Muffled, Clear }` |

### 성능

- 판정 1회 레이캐스트: 직선 2회(앞 · 뒤), 수면 경유 최대 5회(위쪽 1 + 두 구간 × 2).
- 최악 추정: 동시 파문 16개(도망자 3명 × 3개 + 월드 파문 4 + 여유) × 청취자 3 = 재판정 48회 × 최대 5회 = 레이캐스트 240회 / 0.25초.
- 4창 실행(S31) 서버 측정 — 10초 창마다: 재판정 1회(틱) 평균 0.005 ~ 0.034 ms, 최대 1.003 ms(상향 전송 · 로그 포함), 첫 틱 1.934 ms(첫 실행 비용). 동시 추적 파문 최대 3개, 10초당 재판정 3 ~ 47회. 측정값 기준 재판정 1회 ≈ 0.01 ms → 최악 48회 ≈ 0.5 ms / 틱.
