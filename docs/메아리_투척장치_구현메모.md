# 메아리 투척 장치 — 구현 메모

작성: 2026-11-04. 사용자 결정: 기존 유령 역할의 노크 대신, **던진 장치가 바닥에 닿는 순간 파동을 내고 움직임을 흉내 내는 투척 아이템**을 구현한다.

이 문서는 신규 프로토타입의 결정 기록이다. 상세기획서 §3.2의 메아리 유령 역할 및 노크 규칙과 별개의 아이템이다. 상세기획서 §7의 소리통(녹음·설치·원격 재생), 고무오리(투척·착지 유인음)와 관련 있지만 동일한 사양은 아니다. 기존 기획서에는 이 투척 장치의 확정 수치가 없으므로 아래는 튜닝 가능한 구현 시작값이며, 정식 편입 시 기획서 부록 A와 §7에 반영할 대상이다.

## 사용

- NetworkPool_v1_2에서 선반 위 장치를 E로 줍는다. 도망자만 최대 1개 보유한다.
- 3번 슬롯 선택 후 **G를 누르고 있으면 점선 예상 궤도와 착지점을 표시하고, G에서 손을 떼면** 카메라가 바라보는 방향으로 던진다. 조준 중에는 소모되지 않는다. 수중·치료 중에는 사용할 수 없다.
- 슬롯 변경·Esc로 커서 해제·포커스 이탈·피격으로 탈락·라운드 종료는 조준을 취소하며 던지거나 소모하지 않는다. 재개하려면 G를 다시 눌러야 한다.
- 예상 궤도는 투척자 화면에만 표시한다. 서버와 같은 출발 높이·속도·중력·고정 간격·충돌 반사를 사용한다. 벽에 튕기는 경로와 최종 착지를 예측하며, 가려진 점선은 깊이 판정으로 숨긴다. 이동·시점·웅크리기에 맞춰 매 프레임 갱신한다. 누르는 시간은 투척 세기를 바꾸지 않는다.
- 공중에서는 발동하지 않는다. 벽에 부딪히면 튕기며, 바닥 접촉 순간 착지 파동과 준비된 발걸음 효과음을 낸다.
- 착지 이후 투척 방향으로 가짜 발걸음 발생 지점이 순차 이동한다. 벽·턱·낭떠러지에서는 멈춘다.
- 실제 마이크 녹음은 하지 않는다. 첫 버전은 기존 바닥 재질별 효과음을 재사용한다.
- 획득한 아이템은 사용 시 소모되고 리스폰하지 않는다. 탈락·탈출·라운드 초기화 시 보유 상태를 해제한다.

## 권위와 수신 범위

- **서버 권위:** 획득 거리·벽 차단·역할·생존 상태·라운드 단계·보유량·소모·출발 위치·투척 속도·중력·착지·가짜 발걸음 위치.
- 클라이언트는 획득 지점 인덱스 또는 조준 방향만 요청한다. NaN·무한대·비정상 크기 방향을 거부한다.
- 장치의 비행 위치는 투척자에게만 보낸다. 다른 플레이어에게 장치의 정확한 비행 위치를 방송하지 않는다.
- 발걸음은 `SoundWorld.Hear`를 통과한 생존 청취자에게만 전달한다. 벽 뒤에는 기존 8방위 대리 재생 위치와 먹먹한 소리만 전달하고, 정확한 발생 위치·링은 제공하지 않는다.
- UI 보유량은 소유자 전용 TargetRpc다. 라운드 재시작·서버 종료 때 투사체·후속 발걸음·로컬 표시를 정리한다.
- 프리팹·씬 변경 없이 기존 플레이어/라운드 컴포넌트에서 동작한다.

## 검증

`Marco.Network.Editor.DecoyChecks.Run`을 Unity 6000.5.4f1 별도 배치 에디터로 실행한다. 실제 LAN 호스트와 기존 맵을 사용해 획득/보유량 RPC, 단계·역할·거리·인덱스·조준 검증, 중복 사용 방지, 착지 전 미발동, 착지 소리/링, 발걸음 이동, 벽 차단, 수명 종료, 라운드 초기화를 점검한다.

2026-11-04: 별도 프로젝트 복사본에서 컴파일과 위 호스트 실행 검증 통과. 원본 프로젝트의 열린 씬·프리팹은 수정하지 않았다. 검증 로그는 `Logs/DecoyChecks-isolated.log`에 있다. 호스트 초기 역할 동기화를 기다린 후 테스트하도록 구성했다. 복사본의 Unity Search 인덱스 초기화에서 발생한 예외는 아이템 테스트와 별개이며, 테스트는 PASS로 종료했다.

같은 날 홀드 조준으로 변경: Unity 6000.5.4f1 컴파일 및 확장 호스트 테스트 통과(종료 코드 0, `Logs/DecoyAimChecks.log`). 홀드 중 미발사·미소모, 손을 뗄 때 실제 ServerRpc를 통한 투척, 커서 해제·포커스 이탈·슬롯 변경 취소, 예상 착지점과 서버 착지점 일치, 비행 중 라운드 초기화를 확인했다. 점선은 기존 발밑 링의 unlit 셰이더를 재사용하며 별도 씬·프리팹 변경이 없다. 실제 화면에서의 점 크기·가독성은 플레이하며 조정할 대상이다.

2026-11-05 최초 배치(이후 위치 정정): 사용자 사진의 선반을 약품 드럼 선반(o40·o41)으로 잘못 식별했다. 이 위치는 아래 수영장 내부 선반으로 교체했다. 인게임 슬롯 이름은 ‘오리’로 표시한다. 투척·착지·재생 동작은 기존 프로토타입 규칙을 유지한다.

배치 검증: Unity 6000.5.4f1 별도 복사본에서 컴파일 및 표면·겹침·획득 경로 확인 통과(종료 코드 0, `Logs/ItemPlacementFinal.log`). 두 선반 앞에서 픽업까지의 거리는 각각 약 1.242m로 획득 반경 1.5m 안이며, 선반 위 컨테이너가 가리지 않는 위치를 확인했다. 검수 렌더는 `Logs/ItemPlacementFinal/o40.png`, `o41.png`에 있다.

2026-11-05 가시성 수정: 사용자가 두 선반 모두에서 오리가 보이지 않는다고 보고했다. 이전 검수는 위치에 대신 놓은 박스와 편집용 시점을 사용했으므로 실제 스폰·눈높이에서의 가시성을 보장하지 못했다. 기존 12cm 박스 표시는 노란 몸통·머리·주황 부리·눈이 있는 오리 모형으로 교체하고 상판 앞단으로 이동했다. 표시는 마이크 밝기에 종속되지 않는 깊이 판정 unlit 재질을 사용한다. 주변 지형을 밝히지는 않는다. 비행 표시도 같은 오리 모형을 쓰며, 기존 투사체 크기에 맞춰 축소·중앙 정렬한다. 이번 검증은 실제 호스트에서 생성한 두 픽업을 일반 눈높이에서 렌더링해 확인한다.

가시성 수정 검증: 실제 FishNet 호스트의 두 픽업이 모두 활성 상태이며, 일반 눈높이·마이크 밝기 0에서 각 오리가 13,024픽셀로 표시되는 것을 확인했다. 실제 표시를 숨긴 비교 렌더와 대조했으며, 선반 앞에서 획득 경로도 확인했다. 줍기·홀드/릴리스·취소·착지·가짜 발소리·벽 정지·소멸·초기화 검사 PASS, 종료 코드 0 (`Logs/DecoyChecks-ItemFix.log`). 실제 렌더는 `Logs/DuckVisibilityPreview/DuckShelf-1.png`, `DuckShelf-2.png`이다.

2026-11-05 사용자 정정: 요청한 선반은 수영장 안의 장비 선반 2개다. 사진의 비어 있는 북동쪽 h10과 빨간 상자가 놓인 교습풀 서쪽 h01을 맵 렌더로 대조해 상판 앞부분으로 옮겼다. h01은 긴 축이 남북 방향이라 동쪽에서 접근하며 오리도 동쪽을 바라본다. 남서쪽 h02에는 회색 상자가 있으므로 사진 대상에서 제외했다. 현재 배치 검사에는 해당 선반 식별자가 일치하는 지지대가 바로 아래 있는지도 포함해, 단순히 다른 선반에서 잘 보이는 것만으로 통과하지 않도록 했다.

위치 정정 검증 PASS, 종료 코드 0 (`Logs/DecoyChecks-PoolShelves.log`). 실제 호스트 생성 오리 2개의 지지대가 각각 h10·h01임을 확인했고, 선반 앞에서 획득 경로 및 어둠 속 표시(12,242 / 10,374픽셀), 실제 줍기·투척·착지·소멸 검사를 통과했다. `Logs/PoolShelfFinal/DuckShelf-1-Context.png`, `DuckShelf-2-Context.png`에서 오리가 올려진 선반 전체를 사용자 사진과 대조했다. 이 맥락 렌더에서는 검수용으로 카메라만 뒤로 이동해 테스트 플레이어 몸도 보이며, 실제 게임 카메라 동작은 변경하지 않았다.

사용감과 술래 기만 효과는 두 명 이상의 실플레이에서 별도로 평가해야 한다. 이 투척 오리 자체의 실제 음성 녹음·완성형 아트 모델·던지는 팔 애니메이션은 이 프로토타입에 포함하지 않는다.
