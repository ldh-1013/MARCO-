### 2.2 FishNet Unity 6000.5 호환성 패치 (핵심 작업)

Unity 6000.5.4f1에서 FishNet 4.7.2가 그대로 컴파일되지 않음 — 두 가지 Unity 6.5 API 폐기가 원인.

1. `Object.GetInstanceID()` → `EntityId` 전환, 부호 검사 관용구 대체 불가
2. `Scene.handle`의 `int` 암시적 변환 제거 → `SceneHandle` 구조체로 전환

**조치**: 씬 핸들 저장 타입을 `int`→`ulong`(raw data)로 8개 파일에 걸쳐 전면 수정, `NetworkObserver.cs`는 `#if UNITY_6000_5_OR_NEWER` 분기 처리. FishNet 공식 저장소에는 아직 이 패치가 없음 — 이 프로젝트가 자체 대응한 것.

**검증**: Unity 에디터 없이 `dotnet build`로 csproj 12개 전부 컴파일 에러 0 확인, 리플렉션 러너로 Core.Tests 실행해 통과 확인.

### 3.6 스프린트 4 — T8 파문 렌더러 (완료)

`LocalPulsePipelineBehaviour`가 Debug.Log로만 소비하던 델리버리를 **실제 시각 표현으로 교체**. Core 무수정.

### 3.22 스프린트 18b 실기 디버그 — 렌더링·스폰·등록 3건 (원인 확정 후 최소 수정)

씬 분리 실기에서 드러난 문제들. 세 건 모두 **스프린트 18b가 새로 만든 회귀**였다.

- **로비 임시 바닥 ↔ 맵 바닥 결합**: 임시 바닥(윗면 y=0)과 맵 바닥(윗면 y=0)이 **같은 평면**이라, 켜 두면 Z-파이팅으로 바닥이 깨지고 끄면 로비 페이즈에 지면이 없어 pawn이 **무한 낙하**(낙하 한계·리스폰 로직 없음)해 "상대가 접속 안 된 것처럼" 보였다. → 신규 `LobbyPlaceholderFloor`가 `SpawnAnchorRegistry.HasAnchor`(맵 로드 신호)로 렌더러·콜라이더를 전환. 코드가 바닥을 참조하지 않음을 전수 검색으로 먼저 확인했다(결합은 **물리적**이었다).
- **로컬 플레이어 등록 유실**: 모든 pawn이 `OnEnable` 시점에 `IsLocallyControlled` 기본값(true)이라 **원격 pawn도 자기를 등록**해 `Current`를 덮어썼고, 소유권 확정 후 해제되면 `Current`가 null이 됐다. 로컬 pawn은 이미 true라 `SetLocalControl(true)`가 조기 반환해 재등록되지 않았다(호스트는 소유권 확정이 상대 접속보다 **먼저** 끝나 재발행만으로는 복구 불가). → `Unregister` 시 **살아 있는 로컬 pawn 자가 복구** + 조기 반환 전 등록 재확정. `PawnPhaseTeleporter`가 이 값을 폴링하므로, 이 버그가 **스폰 분산이 한 번도 실행되지 않은 진짜 원인**이었다.
- **스폰 겹침**: 앵커 단일 좌표로 전원을 옮겨 시작 즉시 태그 반경(1.2m)에 들어갔다. → 신규 Core `SpawnRing`(반경 4m·8슬롯, 인접 간격 3.06m, `PlayerId % 슬롯` 결정론적). 테스트가 **모든 슬롯 조합이 태그 반경 밖**임을 실제 `TagRules`로 강제한다.
- **중복 카메라**: 마이그레이션이 Game의 `Main Camera`를 Lobby로 옮겼는데 Lobby에 이미 있어 전체화면 카메라 2대 → 중복 렌더링. → 이동 전 대상 씬 확인 + 5단계에서 자동 비활성화.
- **오진 2건 정정**: "머티리얼이 빌트인 Standard"라고 보고했으나 **GUID `933532a4…`는 URP/Lit**이었다(기억 의존 판단 오류, 파일 확인으로 정정). "프레넬 반사" 가설도 사용자 판별 테스트로 배제됐다.

### 3.24 스프린트 20 — 낙하 한계 / 리스폰 (GAP-32)

스프린트 18b 실기에서 "떨어지면 돌아올 방법이 없다"가 확인돼 최소 안전 구현을 넣었다.

- **기획서에 플레이어 낙하/리스폰 스펙 없음**(검색 결과 "리스폰"은 §7 아이템 리스폰뿐). §10.1 맵이 밀폐 실내수영장이라 추락이 설계 시나리오가 아니었던 것으로 보인다 → **GAP-32**.
- **킬 플레인은 y 임계값 방식**(기본 −10m). 중력이 상한 없이 누적돼 프레임당 이동량이 커지므로 **얇은 트리거는 통과해 버린다**(터널링). 좌표 비교는 속도와 무관하고, 맵별 배선도 필요 없다(§15.1 애디티브 맵 구조에 유리). §4.2 잠수와 혼동되지 않도록 수면보다 충분히 아래로 잡았다.
- **소유자(로컬) 처리**로 결정. pawn Transform은 스프린트 8부터 소유자 권위(`NetworkTransform`)라 위치 권한이 이미 클라이언트에 있고, 리스폰은 **라운드 결과를 바꾸지 않는다**(태그·탈출과 다른 점). ServerRpc를 거쳐도 얻는 보증 없이 지연만 는다 → **GAP-33**(이동이 서버 권위가 되면 함께 이전).
- **신규 Core** `FallRecovery`: 안전 지점은 **접지 상태에서만** 기록한다 — 공중 좌표를 기록하면 다시 떨어지는 자리로 복구된다. 킬 플레인 아래 접지도 기록하지 않는다.
- **신규 Presentation** `FallRecoveryDriver`: SceneFlow 오브젝트에 배치(`PawnPhaseTeleporter`와 같은 패턴) — **Player 프리팹을 건드리지 않아** 프리팹 마이그레이션이 불필요하다.
- **`ResetVerticalVelocity()` 추가**: 복구 직후 누적 낙하 속도를 지우지 않으면 다음 프레임에 바닥을 뚫고 다시 떨어진다.
- **역할 상태 불변**: Transform과 수직 속도만 만지고 `IRoleState`/`RoleNetworkSync`/태그에 접근하지 않는다(구조적 보장). 메아리로 떨어져도 메아리로 복구된다.
- 테스트 12케이스 — 총계 368 → **380**. 전 어셈블리 0 error/0 warning. **실기 검증 대기**(§21).

### 3.25 스프린트 21 — 술래 로테이션 (§2.3, GAP-22 해소)

### 3.26 스프린트 22 — 어워드 3종(§8) + 리매치 스폰 리셋

- **근거 절 정정**: 지시서가 지목한 **§6.5는 존재하지 않는다**(§6은 6.4에서 끝). 어워드의 실제 근거는 **§8** 한 줄 — "결과 화면 전환 즉시 어워드 3종 판정(… SoundType.Shout 발생 횟수, 이동거리 대비 파문 발생 0회 여부, 메아리 노크 성공 유인 횟수)". 보조로 §2.3(이름)·§12.5(3열 카드 도식)·§15.4(RoundEnd 판정 시점).
- **⚠ 3종 중 2종은 선행 기능 미구현으로 실제 수여 불가(GAP-37)**: `SoundType.Shout`은 §5.2 음성 파이프라인이 있어야 발생하고(현재 코드에 Shout 생성처가 **하나도 없음**), 메아리 노크는 §3.2 미구현이다. **집계 경로와 표시만 준비**하고 조건을 창작하지 않았다 — 기능이 생기면 호출자만 추가하면 된다.

- 테스트 17케이스 — 총계 395 → **412**. 전 어셈블리 0 error/0 warning. **실기 검증 대기**(§23).

### 3.28 스프린트 24 — 술래 격리 진입 (§10.1)

- **원문은 구역 구성표의 한 셀**: "입구 로비 … 도망자 스폰 지점(**술래는 격리 공간에서 3초 후 별도 진입**)". 전 문서에서 "격리"는 이 한 곳뿐. 확정 도출은 **대상(술래)·시간(3초)** 둘뿐.
- **미명시 4건**: 격리 공간 위치·크기(**구역표에 행 자체가 없음** — GAP-45), 카운트다운 표시(GAP-46), "별도 진입" 방식(GAP-47), 3초 기산점(GAP-48).

## 6. 검증 방법론 메모 (재사용 가능한 프로세스)

이 프로젝트는 Unity 에디터에 실시간 연결하지 않고 파일 조작 + 오프라인 컴파일 검증으로 진행했다. 핵심 장치:

- **스크래치패드 `CoreVerify.csproj` / `PresentationVerify.csproj`**: Unity가 생성하는 `Core.csproj` 등은 소스 파일을 명시적으로 나열하고 에디터가 재임포트하기 전까지 갱신되지 않는다(1회 "헛빌드" 사고 발생 후 발견). 이를 우회하기 위해 `Assets/_Project/**/*.cs`를 glob으로 잡는 별도 csproj를 만들어, Unity 관리 DLL(`C:\Program Files\Unity\Hub\Editor\6000.5.4f1\...`)을 그대로 참조해 컴파일한다.
- **리플렉션 기반 테스트 러너**: `[Test]`/`[TestCase]` 속성을 리플렉션으로 찾아 실행하는 자체 러너로 nunit.framework.dll만 있으면 Unity Test Framework 없이도 테스트를 돌릴 수 있다.
- **meta 파일 수기 생성**: 배경 자동 생성기가 불완전한 meta(1줄짜리)를 만들거나 GUID를 중복시키는 문제를 여러 차례 발견 → 매 작업 후 GUID 중복 검사 스크립트로 전수 검증하는 루틴 확립.
- **씬 YAML 직접 조작**: ProBuilder 없이 큐브 프리미티브로 그레이박스를 만들 때, fileID 중복·참조 무결성·SceneRoots 등록을 매번 파이썬 스크립트로 검증.

이 방법론 덕분에 Unity 에디터가 실제로 열리기 전에 컴파일 에러와 로직 결함 대부분을 잡아낼 수 있었지만, **에디터 전용 동작(렌더링·입력 실제 반응·프로파일링)은 여전히 사람이 직접 열어서 확인해야 한다.**
