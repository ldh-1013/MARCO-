# 권위 모델 — 프로토타입 코드와의 차이

| 항목 | 내용 |
|---|---|
| 작성 | 2026-10-05 |
| 기준 | `docs/마르코_상세기획서.md` §14.2 "전체 권위 모델" 표. **규칙의 정본은 기획서다.** |
| 대조 대상 | 프로토타입 코드 `Assets/_Project/Net` · `Core` · `Presentation`(읽기만 했다. 코드는 수정하지 않았다) |
| 용도 | 새 개발에서 프로토타입 코드를 **그대로 가져오면 안 되는 지점**의 목록 |
| 주의 | 이 문서의 "코드 동작"은 규칙이 아니다. 기획서 본문에는 코드 동작을 규칙으로 적지 않는다 |

## 1. 읽는 법

- 번호는 이 문서 안에서만 쓴다. "표 행"은 기획서 §14.2 표의 항목 이름이다.
- 분류
  - **미구현**: 기획서에 있는 규칙이 코드에 없다. 새로 만들어야 한다.
  - **다름**: 코드가 있지만 규칙과 다르게 동작한다. 규칙에 맞게 바꿔서 가져온다.
  - **구멍**: 서버가 확인해야 할 것을 확인하지 않는다.
- 줄 번호는 2026-10-05 기준이다.

## 3. 문서 쪽 정정 후보(코드가 아니라 기획서 표가 어긋난 곳)

기획서의 규칙끼리 어긋나거나 코드가 더 엄격한 경우다. **A · B · C는 2026-10-05에 기획서를 정정해 해소했다**(아래 "해소" 열).

| # | 위치 | 어긋남 | 해소 |
|---|---|---|---|
| A | 기획서 §14.3 `EchoKnock` 행 | 수신이 **All**이고 페이로드에 `{echoPlayerId}`가 있다. 노크는 비명 · 신음과 **구분 불가 그룹**(§5.1)이고 발생자 식별이 불가능해야 한다(§3.2-1). 파문은 청취자별로 판정해 보내므로(§14.2) 전원에게 발생자 ID를 보내는 행은 이 규칙과 맞지 않는다. 코드는 청취자별 전달이다 | 해소 — 14.3 `EchoKnock`에서 `{echoPlayerId}`와 수신 All 삭제, 청취자별 전달 · 가짜 실루엣 표시 여부로 정정 |
| B | 기획서 §14.3 `SoundPulse` 행 | 페이로드에 클라이언트가 `sourceId` · `position` · `radius`를 보내는 것으로 적혀 있다. 코드는 **소리 종류만** 보내고 서버가 신원 · 위치 · 반경을 확정한다(`Net/PulseNetworkSync.cs:337` `ServerSubmitPulse`). 14.2의 "역할 · ID는 호출자에서 읽는다" 원칙과 맞는 쪽은 코드다 | 해소 — 14.3 `SoundPulse` 페이로드를 `{type}`으로 정정(5.2 8단계도 맞춤) |
| C | 기획서 §5.7 청취자 C(Echo) 줄 | "관전 목적, 정보 참고용 동일 적용"(반경 · 지속 ×1.0, 5.6 차폐 적용처럼 읽힌다). 같은 절 표와 부록 A는 메아리가 **거리 · 차폐 무시**(소나, §3.2-1)다. 코드는 후자다(`Core/SoundPulse/SoundPulseResolver.cs`의 Echo 분기) | 해소 — §5.7 트리를 "거리 · 차폐 무시"로 정정 |

## 6. 대조하지 못한 행

코드에서 해당 동작을 찾지 못했거나 기획서에 규칙이 없어 대조할 수 없었다.

- 메아리 음성 · 탈출자 음성의 채널 분리: 코드에 음성 전송 경로 자체가 없어 대조할 동작이 없다(2절 18번).
- 붕대 후보 중 무작위 배치 · 붕대 줍기: 붕대 코드가 없어 대조할 동작이 없다(2절 6번).
