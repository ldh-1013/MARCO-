## 모션

배틀그라운드 수영을 참고 대상으로 삼아 원본 에셋을 가져오지 않고 기존 CharacterMotion의 절차적 뼈대 포즈를 확장했다. 정지 시 세운 상체와 물장구, 수면 이동 시 상체 기울임·교차 팔 젓기·발차기, 잠수 시 동시 팔 젓기와 수평 자세를 블렌딩한다. 카메라는 수영 중 뼈대의 출렁임을 따라가지 않는다.

공식 참고: https://www.pubg.com/en/news/11057 (수면 애니메이션 및 수영·잠수 전환 변경 안내). PUBG 게임 영상과 나란히 비교하지는 않았다. 술래의 정지·이동 수영 외형은 아래 플레이 모드 점검으로 확인했다. 프로시저 포즈이므로 추가 연출 조정은 가능하다.

### 술래 손발 변형 수정

Demon FBX의 `Hand.L/R`, `Foot.L/R`은 팔·다리 아래가 아니라 `Demon` 루트에 따로 연결되어 있다. 술래 전용 수영 포즈는 실제 관절 방향으로 팔과 다리를 조준하고, 분리된 손발의 위치·회전을 하위 관절과 함께 갱신한다. 원래 관절 길이와 애니메이션의 상대 회전을 유지하며 다음 프레임에는 원래 포즈를 복원한다. 두 Demon CharacterAsset에 누락된 `Leg2.L/R` 매핑도 추가했다. 정지·이동 전환은 속도에 따라 부드럽게 보간한다.

## 검증과 제약

- Unity 6000.5.4f1의 Roslyn과 기존 프로젝트 response 파일로 변경한 Marco.Network 소스를 컴파일: 오류 0, 기존 FindObjectsByType 사용 중단 경고 6개.
- git diff --check 통과.
- 초기 Unity batch 실행은 프로젝트 진입 직후 종료 코드 1로 끝났다(`Logs/SwimmingCompile.log`). 이후 일반 Unity 에디터에서 컴파일과 호스트 플레이 모드 진입에 성공했다.
- NetworkPool_v1_2에서 실제 스폰된 술래를 수면에 배치하고 정지/3m/s 이동을 반복했다. Scene 뷰에서 손발 연결과 정지·이동 자세를 확인했고, 로그에서 정지 시 기울기 8도, 이동 시 55도, 정지 후 8도로 복귀를 확인했다. 점검에는 임시 이동 드라이버를 사용했으며 검증 후 제거했다. 전체 입력·충돌·잠수 흐름과 원격 클라이언트 검증을 대신하는 테스트는 아니다.
- 기존 AudioWaterChecks는 밸브 근처에서 자동 잠수라고 판정하던 이전 임시 구현을 전제로 한다. 새 기능의 통과 근거로 사용하지 않았다.
- 위치는 기존 NetworkTransform 소유자 권위를 유지한다. 숨 계산과 수중 작업 허가는 서버에서 처리하나, 서버 이동 시뮬레이션/부정 이동 방지는 추가하지 않았다.
- 기존의 전체 소리 펄스/정보 공개 시스템은 미완성이다. 이번 링은 현재 렌더러를 이용한 표현이며 정식 SoundType 이벤트·통계 통합은 별도 과제다. 경고 테두리와 질식 음성도 임시 표현이다.

## 에디터 확인 순서

1. NetworkPool_v1_2에서 호스트와 원격 클라이언트로 접속한다. 양 역할의 입수, 3m/s 수면 이동, 정지 부력을 확인한다.
2. 도망자로 Ctrl을 누르고 아래를 보며 W로 하강한다. B/E 밸브와 배수구에 접근하고 Ctrl을 놓아 작업이 끊기는지 확인한다.
3. 14초를 소모해 강제 부상·단발 파문·3초 감속을 확인한다. Ctrl을 계속 누른 동안 다시 잠수하지 않는지 확인한다.
4. 소모 후 2초 회복 대기, 수면/육상 회복 속도, 재잠수 회복 중단, 라운드 재시작 리셋을 확인한다.
5. 풀 네 변에서 Space 출수, 장애물 앞 출수 거절, 메아리 전환, 원격 모션, 수면 위·아래 청취를 확인한다.
