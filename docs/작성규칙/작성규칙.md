# 마르코! 팀 작성규칙

> 4명이 같은 방식으로 개발하기 위한 최소 규칙이다. 게임 규칙 · 수치의 정본은 `마르코_상세기획서.md`(수치는 부록 A)다.

## 규칙 10개

1. **수치 · 규칙은 기획서에서만 읽고, 없으면 `[GAP]` 이슈를 연다. 기획서는 기획만 고친다.**
   이유: 코드에 만든 값이 기획서 대신 정본이 된다.
2. **`main`에 직접 푸시하지 않는다.** 이슈 → 브랜치 → PR → 작성자가 아닌 프로그래머 1명 승인 → Squash 병합. 기획(레포 소유자)의 `docs/` PR만 소유자 우회 + PR 경유.
   이유: 리뷰 없이 들어간 변경이 호출부 누락 · 계층 위반을 만들었다.
3. **커밋 · PR 제목은 `타입(영역): 요약`.**
   이유: Squash 병합하면 PR 제목이 `main`의 커밋 메시지가 되어 기록 · 집계가 쉬워진다.
4. **코드와 테스트는 같은 커밋. 테스트가 깨진 채 푸시하지 않는다.**
   이유: 나중에 붙이는 테스트는 붙지 않는다.
5. **하루를 마치기 전에 자기 브랜치에 푸시한다.**
   이유: 디스크에만 있던 기획 표가 덮어쓰기 사고로 사라졌다.
6. **씬 · 공용 프리팹은 먼저 말하고 연다.**
   이유: 텍스트 병합이 사실상 불가능해 동시에 고치면 한쪽 작업이 사라진다.
7. **에셋과 `.meta`는 같은 커밋. 이동 · 이름 변경은 Unity 에디터에서 한다.**
   이유: `.meta`만 빠지면 GUID가 새로 생겨 참조가 끊긴다.
8. **서버는 클라이언트 값을 믿지 않는다.**
   이유: 클라이언트가 보낸 역할을 믿어 메아리가 밸브를 돌리고 술래가 탈출했다.
9. **AI 산출물도 같은 PR · 리뷰 · 테스트를 거친다. `Co-Authored-By`는 브랜치 커밋과 PR의 "AI 사용" 칸에 남긴다.**
   이유: AI 산출물이라고 덜 보면 같은 사고가 난다.
10. **Unity는 6000.5.4f1 고정**(`ProjectSettings/ProjectVersion.txt`).
    이유: 버전이 바뀌면 전 에셋이 재직렬화돼 모든 PR이 충돌한다.

## 형식 예시

| 대상 | 형식 | 예시 |
|---|---|---|
| 브랜치 | `타입/이슈번호-영문-소문자-설명` | `feat/12-valve-reflow-timer` · `fix/31-knock-reset-on-round-start` |
| 커밋 · PR 제목 | `타입(영역): 한국어 요약` — 기획서 근거가 있으면 끝에 `(§절)` | `feat(core): 밸브 역류 타이머 추가 (§6.1-2)` · `fix(net): 탈출 요청에서 역할을 서버가 읽도록 수정 (§14.2)` |
| 이슈 제목 | `[유형] 요약 (§절)` | `[기능] 배수구 작업 시간 T 계산 (§6.5-2)` · `[GAP] §6.2-1 출구 파문이 탈출자에게도 들리나` |

- 타입: `feat` · `fix` · `test` · `refactor` · `docs` · `art` · `chore` / 영역: `core` · `sound` · `net` · `ui` · `map` · `art` · `docs` · `config`

## 레포 설정 (소유자가 한 번)

- 비공개 레포 — 소유자(기획)가 학생 팩 GitHub Pro를 받는다.
- `main` 브랜치 보호 — PR 필수 · 승인 1명.
- Squash 병합만 허용 · 기본 메시지 = PR 제목.
- 바이너리 에셋은 Git LFS.
- Unity `Reduce version control noise` — 첫 커밋 전에 켠다.
- 설정 파일 3종(`.gitignore` · `.gitattributes` · `.editorconfig`)은 [작성규칙_설정파일.md](작성규칙_설정파일.md)의 것을 쓴다.
