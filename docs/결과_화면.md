# 결과 화면 (포디움)

표시 전용. 라운드가 결정되면(`NetworkRound.IsResultScreenShown`) 각 클라이언트가 맵에서 먼 Y=-20000(로비 CCTV는 -10000)에 결과 무대를 코드로 만들고, 전용 카메라(레이어 30)로 찍어 RenderTexture를 결과 화면 전체에 깐다. 네트워크로 보내는 것은 없고 기존 SyncVar(결과, 역할, 상태, 닉네임)만 읽는다. 리매치 가결(재시작)이나 부결(로비 복귀)로 화면이 닫히면 무대·카메라·RenderTexture를 지운다.

## 구성

- 위: 승패 배너. 도망자 승리 시안 / 술래 승리 레드 / 무효 회색(기획서 12.5). 튀어나오는 등장 뒤 천천히 흔들린다.
- 가운데: 참가자 전원 한 줄. 이긴 쪽은 가운데 단상 위, 진 쪽은 양옆. 바깥쪽부터 한 명씩 떨어져 착지하고 이긴 쪽이 마지막.
  - 도망자: 유니티짱 `unitychan_WIN00` / `unitychan_LOSE00` (무효는 대기 클립)
  - 메아리: `GhostCharacter_Free` 유령 `ghost_idle`(이김) / `ghost_surprised`(짐)
  - 술래: Demon 대기 클립 위에 코드 포즈(이김: 양팔 V 펌프, 짐: 웅크리고 팔 늘어뜨림)
- 캐릭터 아래: 이름(본인은 노란색), 결과(탈출 / 생존 / 메아리 / 술래), 어워드 아이콘 빈칸(기획서 8 판정 로직 생기면 채움).
- 맨 아래: 기존 리매치 투표(15초, 찬성 수/전체, [찬성]). 정보가 다 뜬 뒤(최대 3.6초) 나타난다. 집계는 `NetworkRound.Rematch` 그대로.

## 파일

- `Assets/Scripts/Network/Round/ResultPodium/ResultPodiumStage.cs`: 무대 생성, 연출 시계(`Tick`), PlayableGraph 포즈, 정리.
- `ResultPodiumView.cs`: 화면 열고 닫기, 참가자 목록 만들기, 피드와 투표 줄 그리기(`NetworkTestHud.DrawResult`에서 호출).
- `Assets/Resources/ResultPodium/`: 전용 셰이더 2종(맵 조명·마이크 빛과 무관하게 밝게), `ResultPodiumAssets.asset`(모델·클립 참조).

## 검증

`MARCO > Result > Verify podium rendering`은 별도 미리보기 씬에서 도망자 승리 / 술래 승리 / 2인 / 무효를 렌더링해 `Logs/ResultPodium`에 PNG와 `result.txt`를 남긴다. 캐릭터가 화면 밖으로 잘리거나, 서로 겹치거나, 너무 어둡거나, 모델이 빠지면 FAIL. 스크린샷 아래쪽 어두운 띠는 투표 줄이 덮을 자리다.

`MARCO > Result > Create podium assets`는 `ResultPodiumAssets.asset`의 빈 칸만 채운다. 직접 바꾼 참조는 덮어쓰지 않는다.
