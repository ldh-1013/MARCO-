# 마르코! (MARCO!)

비대칭 멀티플레이 공포 술래잡기. 완전한 암전 속에서 플레이어는 **소리를 내야만** 세상을 볼 수 있고,
소리를 내는 순간 술래에게 위치가 드러난다.

- 엔진: Unity 6000.5.4f1(고정) · 렌더링: URP · 네트워크: FishNet + Steamworks (URP · FishNet · Steamworks는 **계획** — `Packages/manifest.json`에 아직 없다)
- 팀: 6명 (프로그래머 4 · 디자이너 1 · 기획 1)
- 현재 단계: **기획 확정(기획서 v0.6) → 본 구현 시작**

---

## 이 리포지토리의 상태

이전 구현(Phase 3~4, 스프린트 1~27)은 전량 폐기했고, 확정된 기획서를 기준으로 본 구현을 새로 시작한다.
URP · FishNet · Steamworks는 아직 도입 전이다(`Packages/manifest.json`에 없고 렌더 파이프라인 설정도 비어 있다).

이 저장소의 원격은 GitHub(https://github.com/ldh-1013/MARCO-.git)이며, 변경 절차는 `docs/작성규칙/작성규칙.md`를 따른다.

폐기 사유는 코드 품질이 아니라 팀 구성 변경이다. 1인 개발 전제로 짜인 코드를 4명이 읽고
이어받는 비용보다, 확정된 문서를 보고 새로 짜는 비용이 낮다고 판단했다.

다만 **폐기한 코드에서 얻은 검증 지식은 살렸다.** `docs/권위모델_프로토타입_차이.md`가 그것이다
(폐기한 코드를 그대로 가져오면 안 되는 지점). `02-구현검증노트.md`는 더 이상 레포에 없다.

## 절대 규칙 네 가지

**1. 수치의 정본은 기획서 부록 A 한 곳이다.** 본문에는 숫자를 쓰지 않고 참조만 한다.
코드에서도 밸런스 수치는 한 곳에 모으고, 클래스마다 상수를 두지 않는다.

**2. 모든 시스템에 권위를 명시한다.** `서버 권위` / `클라이언트 예측 허용` / `표시 전용` 중 하나.
표기가 없는 시스템은 착수하지 않는다. 통합표는 기획서 §14.2에 있다.

**3. 모듈 경계 = 사람 경계.** 경계를 넘는 호출은 인터페이스 계약으로만 한다.
남의 모듈 내부 클래스를 직접 참조하지 않는다. 계층(Core / Net / Presentation)은 `docs/팀_역할배분.md` 9절.

**4. 값을 바꾸면 결정 로그에 남긴다.** 날짜·변경 내용·근거. "왜 이 값이죠?"에 매번
구두로 답하지 않기 위한 것이다. 결정 로그는 기획서 §0 개정 이력과 `docs/개정이력/`이다.

팀 운영 규칙 전체(브랜치·PR·커밋 등)는 `docs/작성규칙/작성규칙.md`의 10개 규칙을 따른다.

## 착수 전 경고

**잠수 시스템은 한 번도 구현된 적이 없다.** 수면 존 감지가 없어 이전 빌드는 모든 플레이어를
"물 밖"으로 처리했다. 숨 게이지·질식·강제 부상이 전부 미검증이고, **v0.4에서 확정한
수중 밸브·수면 차폐·배수구 설계가 전부 이 위에 얹혀 있다.**

**2층도 존재한 적이 없다.** 물탱크실(밸브 C)과 관람석이 만들어진 적이 없어 층간 차폐 규칙이
한 번도 돌아가지 않았다.

상세는 기획서 §5.9-1(숨 게이지) · §6.1-1(수중 밸브) · §5.6(차폐)을 볼 것.
(예전 우선순위 정리인 `02-구현검증노트.md`는 레포에서 사라졌다.)
