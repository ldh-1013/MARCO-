# MARCO! 프로토타입 씬

## 통합 상태

지금까지 이번 작업에서 만든 기능은 로컬 `ingame` 한 브랜치에 통합했습니다. 별도 작업 브랜치를 전환하지 않고 `Prototype_Lobby`에서 시작해 방 생성/접속 → 게임 시작 → `Prototype_Game`으로 실행하세요. 헌터/서바이버 테스트 씬은 개별 기능 확인용으로 유지합니다. 이번 작업에서 만든 `codex/*` 브랜치 13개는 모든 커밋이 `ingame` 이력에 포함된 것을 확인한 뒤 로컬에서 정리했습니다. 커밋 이력과 실제 코드·에셋·씬은 삭제하지 않았습니다. 기존 `main`, `player`, `ui/ux` 브랜치는 변경하지 않고 유지합니다.

개인 원격 저장소 주소가 정해질 때까지 로컬 커밋만 사용하며 공용 원격에는 푸시하지 않습니다.

## 캐릭터 에셋 이름으로 교체

플레이어의 `CharacterVisualPrototype > Character Asset Name`만 `Demon` 또는 `UnityChan`으로 바꾸면 기존 프리팹, 재질, 1인칭 메시 영역, 뼈대 및 애니메이션 설정이 함께 적용됩니다. 역할/체력/이동 코드는 캐릭터 에셋과 분리됩니다. 원본 캐릭터 모델을 Player 밑에 수동으로 다시 붙이거나 역할별 코드의 뼈 이름을 수정할 필요가 없습니다.

새 에셋은 Project 창에서 프리팹/모델을 선택하고 `MARCO > Characters > Register selected prefab`으로 한 번 등록하세요. 생성된 `Assets/Resources/CharacterAssets`의 등록 정보에서 클립 선택, 모델 크기/발 위치, 눈높이 보정(`First Person Eye Offset`)을 확인한 뒤 그 등록 정보의 이름을 Character Asset Name에 입력합니다. 등록 메뉴는 스킨 메시의 Read/Write를 켭니다. Humanoid Avatar는 표준 관절을 자동 매핑합니다. Generic/특수 리그는 Generic Bones에서 표준 관절과 실제 본 이름을 최초 한 번 연결해야 합니다. 따라서 아무 뼈대/애니메이션도 없는 에셋까지 이름만으로 호환되는 것은 아닙니다. 등록되지 않은 이름은 오류로 알려주며 이전 캐릭터로 조용히 대체하지 않습니다.

`Demon.asset`에 특수한 Generic 뼈 이름이, `UnityChan.asset`에 기존 Humanoid 클립이 들어 있습니다. 향후 에셋 변경은 게임 코드가 아닌 이 등록 정보에서 처리합니다.

## 본인과 외부에서 보는 동작

`CharacterMotionPresenter`가 등록 에셋의 원본 Animator를 공통으로 구동합니다. WASD 걷기, Left Shift 달리기, 대기, 공격/상호작용과 위·아래 시선을 연결합니다. Unity-Chan은 RUN00_F를 사용하며 별도 달리기 클립이 없는 Demon은 걷기 클립을 빠르게 재생합니다. Humanoid는 가슴·목·머리에 시선 회전을 분배하고 독립 손목을 사용하는 Generic 리그는 목·머리만 회전합니다. 상호작용 클립이 없는 에셋은 기존 팔 관절을 회전하는 임시 도달 자세를 사용합니다. 새 메시나 도형 팔을 만들지 않습니다. 본인 화면과 외부 화면 모두 하나의 원본 몸·뼈대·애니메이션을 그대로 사용합니다.

## 기본 확률 배정과 개발용 역할 전환

게임 시작은 방장이 **실제 참가자 중 헌터 1명을 균등 무작위**로 뽑고 나머지를 서바이버로 배정합니다. N명이면 각자의 헌터 확률은 1/N, 서바이버 확률은 (N-1)/N입니다. 방장도 동일한 확률이고, 1인 기본 시작은 100% 헌터입니다. 시작 전에 로비에 확률을 표시하며 방장이 결정한 동일한 배정을 전원에게 보냅니다.

에디터 또는 Development Build의 통합 씬에서 **F10**으로 본인의 헌터/서바이버 역할을 전환할 수 있습니다. Esc로 메뉴를 열어 `[DEV] 역할 전환 (F10)` 버튼을 눌러도 됩니다. 혼자라면 두 역할을 자유롭게 오가며 허수아비/가짜 참가자를 만들지 않습니다. 여러 명이면 서바이버→헌터 때 기존 헌터와 역할을 교환하고, 헌터→서바이버 때 다른 참가자 중 새 헌터를 무작위로 정해 항상 헌터 1명을 유지합니다. 다른 참가자의 역할도 바뀌므로 멀티 테스트 전에 서로 확인하세요.

게스트의 치트 요청은 본인 소켓 ID로만 처리하며 방장의 승인·동일 역할 목록을 전원에게 전달합니다. 씬을 다시 로드하거나 연결을 끊지 않고 위치·방향·참가자 ID·동작 전송 순번을 유지합니다. 역할에 맞게 원본 에셋·입력·카메라·마이크·체력바를 교체하고 F8 전체 시야도 유지합니다. 전환한 역할의 체력·고스트 상태·공격 쿨다운은 새 테스트 상태로 초기화합니다. F10/개발 프로토콜/역할 교체 코드는 Release 빌드에 포함되지 않습니다. 기존 역할별 테스트 씬은 그대로 유지합니다.

개발용 역할 전환과 기본 확률 배정도 현재 `ingame`에 포함됩니다.

Unity 배치 검증 297개를 통과했습니다. 균등 확률 샘플, 실제 호스트/게스트 TCP 역할 요청·중계, 참가자 ID/위치 유지, 전송 순번 지속, 단일 입력/카메라/마이크, 반복 1인 전환과 기존 몸 가림 회귀 검사를 포함합니다. 모든 프로토타입 런타임 스크립트는 개발 정의 없이 별도로 컴파일했고 역할 치트 API 6개가 Release 어셈블리 메타데이터에서 제외됨을 확인했습니다. 완성된 플레이어 배포 빌드 자체를 생성한 검증은 아닙니다.

## 참가자별 캐릭터와 동작 전송

현재 게임 구현은 게임 시작 때 참가자 ID·역할·등록된 에셋 이름을 전원에게 전달하고 실제 참가자 수만큼 몸을 배치합니다. 통합 게임의 에셋 변경은 로비의 `RoomSessionPrototype > Hunter Asset Name / Survivor Asset Name`에서 이름을 바꾸세요. 방장의 선택이 각 클라이언트의 원본 몸과 본인 팔다리에 동일하게 적용됩니다. 역할 테스트 씬은 Player의 `Character Asset Name`을 사용합니다. 새 에셋은 모든 클라이언트 프로젝트에 동일한 등록 이름으로 포함되어야 합니다. 미등록 에셋으로 시작하면 오류를 표시합니다.

로컬 플레이어는 위치·수평 회전·위/아래 시선·이동속도·달리기·공격/상호작용 카운터를 약 20Hz로 전송합니다. 방장이 실제 소켓의 참가자 ID를 확인하여 다른 참가자에게 중계합니다. 상대는 보간된 위치와 원본 에셋 관절/애니메이션으로 표시되며 카메라·입력·마이크·체력바는 본인에게만 켜집니다. 중복/이전 순번, 위조 ID, NaN/Infinity 및 범위를 벗어난 값은 거부합니다. 전송은 비동기 제한 큐를 사용합니다. 게임 중 새 참가자는 받지 않으며 일반 참가자가 나가면 그 몸을 제거하고, 방장이 나가면 전원 로비로 돌아갑니다. 1인 게임에는 헌터 본인만 남고 가짜 서바이버를 만들지 않습니다. 최대 참가자는 방장 포함 16명입니다.

이것은 **움직임과 외형 동작의 동기화**이며 완성된 멀티플레이 판정 시스템은 아닙니다. 태그 명중·목숨·치료·메아리 상태는 아직 각 클라이언트의 로컬 판정입니다. 따라서 원격 공격의 애니메이션을 받는 것만으로 체력을 바꾸지 않습니다. 이동 검증/치트 방지·서버 권위 판정, 지연 보상, 인터넷 Relay는 별도 작업입니다. 양쪽 모두 같은 버전의 프로젝트를 사용하세요.

## 에디터에서 배치 수정

Play 모드를 끈 상태에서 씬을 열면 Hierarchy에 Player, Main Camera, Prototype Ground, Directional Light가 보입니다. 역할 테스트 씬에만 별도 테스트 Target이 있습니다. 선택한 뒤 Scene 뷰의 이동/회전/크기 도구 또는 Inspector의 Transform으로 직접 수정하고 씬을 저장하세요. 실행 시 배치를 다시 생성하거나 초기 위치로 덮어쓰지 않습니다.

카메라는 Player의 자식입니다. 등록 정보의 `First Person Eye Offset`으로 원본 Head 관절 기준 눈 위치를 바꾸고, Camera 컴포넌트에서 FOV를 조절할 수 있습니다. Player의 이동속도/마우스 감도, Hunter의 태그 거리/쿨다운, Survivor의 상호작용 거리도 Inspector에서 수정할 수 있습니다. Play 중 이동한 위치는 종료하면 되돌아가므로 배치 수정은 Play 종료 후 저장하세요.

- `Prototype_Lobby`: 실제 TCP 방 생성/접속. Create room 후 IP 복사 → 다른 인스턴스의 Join 입력칸에 붙여넣습니다. 로비 참가자 수를 동기화합니다. 방장만 게임 시작 버튼을 누를 수 있고, 시작하면 연결된 전원이 `Prototype_Game`으로 이동합니다. 방장이 참가자 중 헌터 1명을 무작위로 배정하고 나머지는 서바이버가 됩니다. 1인 실행도 개발 확인용으로 허용합니다.
- `Prototype_Game`: 헌터와 서바이버를 같은 월드에 배치한 통합 씬입니다. 로비의 게임 시작을 통해 배정된 역할의 입력·카메라·마이크·HUD만 켜집니다. 이 씬을 직접 Play해도 먼저 `Prototype_Lobby`가 뜨며, 방 생성/접속 후 게임 시작으로 돌아옵니다. 가운데의 별도 허수아비/치료용 테스트 대상은 제거했습니다. 기존 역할 테스트 씬의 허수아비는 유지합니다.
- `Prototype_HunterTest`: WASD 이동과 좌클릭 태그 판정(사거리 1.2m, 전방 45도, 명중 2.5초/헛스윙 1.5초 쿨다운)을 확인합니다.
- `Prototype_SurvivorTest`: WASD 이동과 E 상호작용/치료 대상 테스트를 확인합니다.

## 임시 서바이버 체력바

서바이버 테스트/통합 씬의 임시 체력바는 우하단에 목숨 `2.0 / 2.0`과 4칸 막대로 표시됩니다. 첫 태그는 1.0, 붕대 효과는 +0.5, 치료는 2.0으로 복원됩니다. 헌터 화면에는 상대 체력이 보이지 않고, 메아리가 되면 체력바가 숨겨집니다. 에디터/개발 빌드의 F6(태그), F7(초기화), F9(메아리)로 변화를 확인할 수 있습니다. 붕대 아이템 자체는 아직 구현하지 않았습니다.

## 추가 팔 없는 원본 몸의 1인칭

현재 원본 몸 1인칭 구현에서는 기존 본인용 팔·다리 렌더러와 복제 뼈대, 카메라 기준 IK/팔 벌리기·크기 보정을 제거했습니다. `FirstPersonBodyView`는 추가 신체 오브젝트를 만들지 않습니다. 카메라가 원본 캐릭터의 Head 위치에 놓이고, **원래 몸의 같은 SkinnedMeshRenderer와 같은 손·다리 관절**을 직접 봅니다. Scene 뷰나 상대 화면에도 몸과 팔 한 쌍만 존재합니다.

본인 카메라를 그리는 동안만 기존 렌더러의 머리·목·머리카락 삼각형을 숨겨 얼굴 내부가 시야를 막지 않게 합니다. 그 카메라가 끝나면 즉시 전체 원본 메시를 복원하므로 Scene/상대 카메라에는 머리가 정상 표시됩니다. 이는 같은 렌더러의 표시 영역만 조절하며 팔이나 신체를 더 렌더링하는 것이 아닙니다. 원본 FBX·프리팹·재질과 뼈대의 형태/크기는 변경하지 않습니다. 현재 Built-in Render Pipeline의 카메라 콜백을 사용합니다.

팔은 원본 대기·걷기·공격·상호작용 자세 그대로 움직입니다. 대기 자세가 팔을 내리고 있다면 정면에서 팔이 항상 올라와 보이는 형태를 강제하지 않습니다. 아래를 보면 실제 몸과 다리·신발이 보이고, 공격/상호작용으로 원래 팔이 시야에 들어옵니다. 원래 에셋의 무기도 하나만 존재합니다. 메아리 때 육체 숨김/복원과 체력바는 유지합니다.

새 에셋은 앞의 등록 절차를 그대로 사용합니다. Humanoid의 Head/Hand 관절은 자동으로 찾고 Generic은 최초 등록 매핑을 사용합니다. 눈높이만 등록 정보의 `First Person Eye Offset`에서 조절합니다. 제거된 Resting Hand/Shoulder Offset/Arm View Scale 설정은 더 이상 사용하지 않습니다. 이전 복사 팔 배치 방식은 원본 몸 표시 방식으로 대체됐습니다.

## 아래를 볼 때 몸/어깨가 찢어지는 현상 수정

현재 몸 가림 수정은 머리 가림 처리의 잘못된 높이 판정을 제거합니다. 기존 코드는 스케일이 큰 imported renderer의 BakeMesh 정점에 Transform 스케일을 다시 적용해 몸통까지 머리 영역으로 판정했습니다. 이제 가중치가 있는 원본 몸은 머리·목 관절에 주로 연결된 정점만 가리고, 팔 가중치가 있는 정점은 보호합니다. 가중치 없는 별도 얼굴 부품에만 월드 공간 bounds 판정을 적용합니다. 새 팔·뼈대·카메라를 추가하지 않으며 원본 FBX/재질도 바꾸지 않습니다.

로비에서 진입한 실제 통합 씬의 0/45/70/85도 시선과 아래를 보는 대기·공격·걷기·달리기를 캡처합니다. 배치 검증은 164개 검사를 통과했으며, 머리가 아닌 몸/팔/다리 삼각형 보존, 정점·스킨 가중치·bind pose 불변, 카메라 렌더 이후 원본 복원 검사를 포함합니다. 헌터/서바이버 역할 테스트에서도 동일하게 검사합니다.

## 마이크 시야 프로토타입

두 역할 테스트 씬은 기본적으로 완전 암전입니다. 마이크 RMS/dBFS가 Silence Db를 넘으면 중앙 원형 시야가 열리고, Full Vision Db에 가까워질수록 반경이 커집니다. 음량이 줄면 시야가 닫힙니다. Inspector에서 임계값/최대 반경/닫힘 속도를 조절합니다. `Left Alt`는 즉시 암전과 강제 뮤트입니다.

방 접속은 같은 PC(127.0.0.1), 같은 LAN 또는 VPN에서 연결 가능한 호스트 IP를 사용합니다. 자동 감지 주소가 잘못된 어댑터의 IP라면 Create room 전에 공유 주소를 수정하세요. 코드는 주소를 담고 있으며 인터넷 Relay나 서버 권위 판정은 아직 구현하지 않았습니다.

`F8` 전체 시야는 에디터와 Development Build에서만 컴파일되는 디버그 치트이며 Release 빌드에는 포함되지 않습니다.

두 역할 테스트는 멀티플레이 동기화 대신 각 씬 안의 독립 대상 오브젝트로 판정 흐름을 검증합니다.

통합 씬은 씬 전환·역할 배정에 더해 참가자별 몸과 이동·시선·행동 표시를 공유합니다. 목숨·명중·치료·메아리 판정은 아직 동기화되지 않습니다. 세션과 TCP 연결은 씬 이동 중 유지되고 게임 중에는 새 참가자를 받지 않습니다. Esc로 커서를 풀면 오른쪽 위의 `게임 나가기 · 로비로` 버튼으로 나갈 수 있습니다. 호스트가 나가면 게스트도 로비로 돌아옵니다.

통합 게임에는 게임 씬 직접 실행 시 로비 우선 진입과 통합 씬 허수아비 제거가 포함됩니다. Play 시작 시 진입 상태를 초기화하므로 Domain Reload를 끈 에디터에서도 지난 게임의 역할로 바로 시작하지 않습니다.

통합 씬 검증: Unity 메뉴 `MARCO > Verify combined scene`은 두 역할의 입력 소유권, 활성 카메라/AudioListener/마이크 각 1개, 씬 참조와 빌드 등록을 검사합니다. 실행 중이거나 저장하지 않은 씬이 있을 때는 먼저 종료/저장하세요.

임시 도형 팔·다리는 원본 캐릭터 에셋으로 대체됐습니다. 체력바와 로비 진입 흐름은 유지합니다.
